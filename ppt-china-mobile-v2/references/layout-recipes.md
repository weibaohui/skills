# 高密度布局配方

## 先划分材料，再分配空间

将一页内容拆成“导语—主模块—子模块—对象”。模块可以承载完整的小型页面，内部自行建立标题、图、表和说明的层级。按字数、图形复杂度和阅读顺序分配面积，不平均分配后强行缩字。

建议先估算每块容量：

```text
字形尺寸 px = 字号 pt × 4/3
每行可用宽度 = 模块宽度 − 左右内边距 − 序号/图标占位
预估全角字数/行 ≈ 每行可用宽度 / 字形尺寸
可用行数 ≈ 正文区高度 / 预期行高
```

估算只用于比较布局，不能替代渲染。粗体、英文长词、数字、标点、实际字体和表格边距都会改变换行。为文本保留余量，不能按理论最大字数刚好塞满。

## A. 项目方案四分区

适合“功能架构—建设内容—成果—指标”同时呈现。左窄右宽，上大下小，不是四个等面积卡片。

这些配方只设计新模板正文安全区内部。以 `internal-report-template` 第3页为基础，页眉与Logo沿用模板。默认安全区x=24、y=90、w=1232、h=606px；按内容确定导语高度、上下区比例和左右列宽，不再使用旧截图整页坐标。

模块标签贴在上边框附近或跨骑边框，留出标签本身的空间。不要让正文从标签底下穿过。标题长度或段落高度变化时重算块高，不固守坐标。

典型嵌套树：

```text
页面
├─ 固定模板标题 / Logo
├─ 背景与目标
├─ 功能架构
│  ├─ 展示层
│  ├─ 能力域网格
│  │  ├─ 能力域A：域标题 + 细项标签
│  │  ├─ 能力域B：域标题 + 细项标签
│  │  └─ 其余能力域
│  └─ 采集或支撑层 + 方向连接
├─ 建设内容：序号 + 小标题 + 段落
├─ 预期成果：完整论述或分项条目
└─ 技术指标：指标 + 条件 + 数量/单位
```

先画各层边界，再画层内网格，最后布置细项和连接线。外框线宽、模块标题和子项字号不要一起等比缩小。

## B. 大架构 + 右侧举措栏

适合体系建设、运营能力优化或一组关键举措。主体左区约60%–68%，右区约30%–36%，留出独立沟槽。

- 左区容纳完整架构，可分为服务层、能力层、支撑层；能力层再分基础能力和扩展能力。
- 右区按实际主题纵向分成2–4块，蓝色标题条搭配短标题与详细说明。
- 导语用淡蓝横带说明建设目标；红色只标注举措名称或需要突出的变化。
- 状态区分如已建、优化、新增应有简短图例，图例颜色不得暗示未经确认的建设状态。
- 架构中功能域多时使用行列网格或层次带，不把每个功能都做成独立的大卡片。

## C. 全幅分层架构

适合“管理中心—平台—数据支撑—基础防护”等体系关系。

- 全幅横向展开能力域，纵向表达支撑层级。
- 各层可用淡绿、淡蓝、淡黄区分，域内仍以白底标签为主。
- 横向平台可有不同宽度，宽度与子项数量对应。
- 跨域能力可用横跨多个列的窄带；明确它覆盖哪些对象。
- 标题、图例、跨层说明须留在可编辑对象中。避免图中只有大量平行小盒子而没有层级含义。

## D. 矩阵 + 证据/说明

适合需求分解、能力对照、建设任务、验收指标或演进计划。

- 让矩阵占据主要面积；说明按对应行放在侧栏或表后短区。
- 数值、指标、状态、责任和时间使用原生表格；可合并标题单元格，但避免让长段落硬塞进窄列。
- 长文列采用左对齐，数量与日期可居中；同列保持一致。
- 表格嵌在主模块里时仍独立规划行高、列宽和字体。外部主模块标题与表头不重复堆叠。

## E. 一页内容压入一个模块

用户需要把原本一页体量压成局部时，采用“重排后压缩”：

1. 保留原内容的层级与对应关系，移除重复页头、重复Logo及重复导语。
2. 根据目标模块的宽高重排：宽模块转横排、窄模块转纵排；不能只做整页等比缩小。
3. 将长段落转为有标题的短段、关系表或图中注释，保留事实、条件和数字。
4. 合并重复标签，压缩内部空白及装饰占位，将极小字号、紧凑间距与嵌套结构共同用于内容压缩。
5. 将重建的文字、图形和连接线按模块组合，便于整体移动；仍可进入组合逐项编辑。
6. 以模块放大预览检查最细文字。精确复现时若无法辨认原图标签，回查来源或标记待核，不自行补齐。

只有用户明确接受静态图片，或该部分本来就是需保真的原始截图时，才用整块图片。不要因生成更省事就把重建目标栅格化。

## 密集布局与溢出处理

从布局规划阶段同时设计小字号、紧凑间距、嵌套分区与图文比例，充分组织高密度内容。发生溢出时，结合块的面积、层内顺序、分栏、字号和行距调整，去掉重复表述，保留有效信息。不得裁切尾行、把文字压到边框或遮住连接线。若固定页数与完整内容仍无法兼容，报告具体拥挤模块和所需取舍，不静默删减或添加页数。
